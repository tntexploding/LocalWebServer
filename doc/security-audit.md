## 已修复的重要问题

- 旧便携包会直接复制构建主机的 Node.js，可把过期运行时带入发行物。
- 外发请求缺少统一地址/端口策略，HTTP 路径可改变客户端 Origin，重定向可能泄露请求头。
- HTTP 正文、响应、WS 消息、连接数和命令输出存在无界或过大的资源消耗面。
- 本地进程继承全部环境变量，工作目录和脚本路径未对符号链接后的真实路径做边界检查。
- 队列与状态日志可能保存带查询参数的目标 URL，服务器 500 响应可能泄露内部异常细节。
- 原始配置可保存敏感字段或敏感 URL 查询参数的明文。
- 最终打包首次运行时，新发布的 `GHSA-c96f-x56v-gq3h` 高危公告使安全门主动失败；
  `find-my-way` 已从 9.6.0 更新至修复版 9.7.0，并重新执行干净安装和全部审计。
- 2026-08-15 复审发现 `brace-expansion`、`fast-uri`、`js-yaml`、`nanoid` 和 `postcss`
  的新公告；锁文件已更新至修复版本，并通过干净安装、完整审计和全部测试。
- Node.js 2026-07 安全发布后，源码安全基线与便携运行时已从 24.18.0 提升至 24.18.1。

## 剩余风险

- 程序不提供 TLS；跨主机明文 HTTP/WS 不应承载令牌或敏感消息。
- 显式允许的公共域名存在检查后由底层客户端再次解析的时间窗口；高安全场景应使用固定
  地址、可信 DNS 和出口防火墙。
- 入站端点没有通用业务级身份协议或全局速率限制。默认回环白名单可降低风险；对局域网
  开放时应由上游鉴权、代理限流和防火墙补足。
- 预定义命令仍以服务账户权限运行。白名单只能约束入口，不能证明被允许程序或脚本无害。
- 凭据扫描基于已知模式，无法证明任意业务文本中不存在秘密；发布前仍需人工审阅。
- 本轮不是第三方渗透测试，也没有对所有外部 QQ 插件或自定义脚本进行供应链审计。
